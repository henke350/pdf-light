# pdf-light v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small, fast, pure-Rust Windows PDF app that reads, searches, deletes pages from, and exports pages of one PDF.

**Architecture:** One Cargo package. A UI-free library (`src/lib.rs` + modules) holds all PDF logic and is unit/integration tested. A thin eframe app (`src/main.rs` + `src/app/`) draws the UI. Rendering and text extraction run on worker threads that each open their own `hayro` `Pdf` from shared `Arc<Vec<u8>>` bytes; results come back over `std::sync::mpsc` channels.

**Tech Stack:** Rust (edition 2024), eframe/egui 0.37, hayro 0.9, hayro-interpret 0.9, lopdf 0.47, image 0.25 (PNG), tiff 0.11, rfd, thiserror, anyhow.

**Spec:** `docs/superpowers/specs/2026-11-18-pdf-light-design.md` (read it first; this plan argues from it).

## Global Constraints

- Pure Rust; crates.io dependencies only; no git dependencies; no PDFium/MuPDF ever ("Pure Rust wins over speed").
- Windows 11 target; edition 2024; latest stable Rust.
- `hayro = { version = "0.9", features = ["embed-fonts"] }`; `hayro-interpret = "0.9"` (default features: embed-fonts, embed-cmaps); `lopdf = "0.47"`; `eframe = "0.37"`; `image = { version = "0.25", default-features = false, features = ["png"] }`; `tiff = "0.11"`; `rfd`; `thiserror` (library); `anyhow` (app only).
- No `unwrap()`/`expect()` outside tests. `cargo fmt --check` and `cargo clippy --all-targets -- -D warnings` clean after every task. `#[expect(...)]` with a reason instead of `#[allow(...)]`.
- Follow `.claude/skills/rust-best-practices` first, then the actionbook rust-skills in `.claude/skills/`.
- The UI thread never renders pages or extracts text.
- The original file is never modified except by an explicit Save the owner confirmed; every save writes a temp file in the target folder and renames it into place.
- Comments explain a Rust idea where it first appears (ownership/borrowing, `Result` and `?`, traits, `Arc`/threads/channels, lifetimes) for a Rust newcomer. Keep them short.
- Release profile: `lto = true`, `codegen-units = 1`, `strip = true`, `opt-level = 3`; release `.exe` under ~15 MB.
- Test names describe behaviour: `save_with_pages_should_keep_only_listed_pages`.
- Work on branch `feature/v1`, created from `design/initial`; commit after every task; never push without the owner asking. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Unreadable or password-protected file** → a clear message (`PdfError::Invalid` / `PdfError::Encrypted`), never a panic. Garbage and empty files tested in Task 2; the `Decryption` → `Encrypted` mapping is checked by the owner with a real protected PDF in Task 7's manual check.
2. **Very large page or very high export DPI** (A0 at 600 DPI, hayro's 65,535 px side limit) → `PdfError::TooLarge` before allocating, never a crash or truncated image. Test in Task 2 and Task 6.
3. **Page with no text layer** (blank or scanned) → search finds nothing on it and moves on; no panic. Test in Task 3.
4. **Save goes wrong** (target folder missing, file lopdf can't parse) → error shown, original untouched, no half-written or temp file left. Test in Task 5.
5. **Export would overwrite files, or the PDF has over 999 pages** → owner is asked first; file names stay sortable (`_p0001` when >999 pages). Test in Task 6.

Shared types used across tasks (defined in Task 2/3, listed here so every task sees them):

```rust
// src/error.rs
#[derive(Debug, thiserror::Error)]
pub enum PdfError {
    Io(#[from] std::io::Error),          // "couldn't read or write the file: {0}"
    Encrypted,                           // "this PDF is password-protected, which pdf-light doesn't support yet"
    Invalid,                             // "this file isn't a PDF pdf-light can read"
    TooLarge { width: u64, height: u64 },// "the page is too large to render at this size ({width} × {height} px)"
    NoPagesLeft,                         // "a PDF needs at least one page"
    Save(String),                        // "couldn't save the PDF: {0}"
    Image(String),                       // "couldn't write the image: {0}"
    Cancelled,                           // "cancelled"
}

// src/text.rs — rectangle in page points, origin top-left, y down (same space as rendering at scale 1)
#[derive(Clone, Copy, Debug, PartialEq)]
pub struct PageRect { pub x0: f32, pub y0: f32, pub x1: f32, pub y1: f32 }
```

### Task 3: Text with positions, and search

**Files:**
- Create: `src/text.rs`, `src/search.rs`, `tests/text.rs` (search unit tests live in `src/search.rs` under `#[cfg(test)]`)

**Interfaces:**
- Consumes: `document::open_pdf`, `PdfError`.
- Produces:
  - `text::TextGlyph { pub text: String, pub rect: PageRect }`
  - `text::extract_glyphs(pdf: &Pdf, index: usize) -> Vec<TextGlyph>` — glyphs in content-stream order.
  - `search::PageText { pub chars: Vec<char>, pub rects: Vec<PageRect> }` (same length)
  - `search::build_page_text(glyphs: &[TextGlyph]) -> PageText`
  - `search::normalize_query(q: &str) -> Vec<char>` — lowercase, whitespace runs → one `' '`, trimmed.
  - `search::find_in_page(text: &PageText, query: &[char]) -> Vec<Vec<PageRect>>` — non-overlapping matches, left to right; each match's char rects merged into one rect per line.

**`extract_glyphs` algorithm** (not determined by the signature):
- `TextCollector` implements `hayro_interpret::Device`; only `draw_glyph_run` does work, everything else is a no-op (like hayro-interpret's `examples/extract_html.rs`).
- Create `Context::new(page.initial_transform(true).to_kurbo(), Rect::new(0,0,w,h), &InterpreterCache::new(), pdf.xref(), InterpreterSettings::default())` and call `interpret_page(page, &mut ctx, &mut collector)`. This puts coordinates in the same space as rendering at scale 1.
- For each glyph: `t = props.transform * glyph.transform()` (glyph space: 1000 units per em, y up). Glyph box in glyph units: x from 0 to `w`, y from −200 to 800. `w` = distance to the next glyph's origin in the same run, mapped back through `t.inverse()` (if > 0); else the Type3 `advance_width()`; else the outline's bounding box `x1` if > 0; else 500. Rect = `t.transform_rect_bbox(box)`.
- Text: `as_unicode()` → `BfString::Char(c)` / `BfString::String(s)`; `None` → skip the glyph.

**`build_page_text` rules:** For each glyph, if `text` is whitespace, push one `' '` (unless the last char is already `' '`). Otherwise, if there is a previous glyph, insert `' '` (rect = previous rect) when the vertical centres differ by more than half the glyph height (new line) or the horizontal gap `cur.x0 − prev.x1` exceeds 0.25 × glyph height. Then push each lowercase char of `text` with the glyph's rect (a ligature "fi" gives two chars sharing one rect).
